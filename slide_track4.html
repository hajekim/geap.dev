🔴 Part 3. Admin & Security

전사 AI 인프라 & 보안 거버넌스 가이드

클라우드 인프라 관리자, 정보보호최고책임자(CISO), 기술 의사결정권자를 대상으로 합니다.
기업 내 안전한 생성형 AI 도입을 위한 데이터 격리, 권한 제어, 보안 관제 및 투자 효과(ROI) 검토 방안을 다룹니다.

Step 3.1 인프라 설정

GCP 프로젝트 분리 및 4대 필수 API 활성화

Gemini Enterprise의 안전한 전사 배포를 위해 환경별 프로젝트 분리 기준과 4대 필수 API를 설정합니다.

🏛️ 환경별 3단 프로젝트 격리

운영(Prod) / 개발(Dev) / 감사(Audit) 프로젝트로 완전 분리하여 리소스 간섭을 방지하고 최소 권한 원칙(PoLP)을 적용합니다.

🔌 4대 필수 활성화 API

  • gemini.googleapis.com: Gemini Enterprise 핵심 API
  • discoveryengine.googleapis.com: Vertex AI Search 커넥터
  • logging.googleapis.com: Cloud Audit Logs 감사 수집
  • cloudkms.googleapis.com: 고객 관리 암호화 키 (CMEK)
Step 3.1 인프라 설정

다중 프로젝트 가용성 & 멀티 리전 이중화

서비스 연속성 보장 및 장애 복구(DR) 요건 충족을 위해 멀티 리전 배포 구조를 적용합니다.

🌐 멀티 리전 배포 구조

  • asia-northeast3 (서울): 주요 운영 트래픽 처리 및 색인 데이터 로컬 보관 (국내 데이터 주권 준수)
  • us-central1 (아이오와): 재해 복구(DR) 대비 글로벌 백업 리전 활용

🛡️ 네트워크 및 암호화 통제

  • VPC Service Controls: 비인가 외부 IP 및 단말의 통신 차단
  • Cloud KMS (CMEK): 90일 주기 자동 회전 고객 관리 키로 저장 데이터 암호화
Step 3.1 인프라 설정

심화: VPC SC 및 KMS CMEK 관리 기준

사내 데이터 보호를 위한 보안 경계(Service Perimeter) 설정 및 고객 관리 암호화 키(CMEK) 운영 주기 관리입니다.

💡 보안 경계 통제 기준

VPC SC 경계 내부 리소스 간의 통신만 허용되며, 승인되지 않은 외부 IP 주소 및 미인증 단말에서의 데이터 입출력을 철저히 제어합니다.

  • CMEK 주기적 자동 회전: 설정된 주기(예: 90일)에 따라 암호화 키를 자동 회전하여 암호키 노출 범위를 최소화합니다.
  • Zero Data Ingestion: VPC SC 경계 밖으로 사내 비정형 문서가 유출되는 것을 차단합니다.
Step 3.2 인증 관리

WIF 키리스 인증 & Cloud Identity 연동

장기 보안 자격증명(`.json` 키 파일) 사용의 위험을 제거하기 위해 Workload Identity Federation (WIF) 기반 인증을 구성합니다.

🔑 WIF 기반 키리스(Keyless) 연동

사내 IDP(Okta, Entra ID 등)와 구글 클라우드를 OIDC 표준 프로토콜로 연결하여 정적 키 발급 없이 단기 일시 토큰으로 인증합니다.

👥 인사 조직 정보 자동 동기화

인사 관리 시스템(HRIS)과의 동기화를 통해 퇴직 및 부서 이동 시 IAM 접근 권한이 자동 갱신 및 해지되는 파이프라인을 운영합니다.

Step 3.3 커넥터 거버넌스

M365 / ServiceNow 연동 및 실시간 ACL 동기화

Google Workspace 외에 Microsoft 365(Outlook, OneDrive) 및 ServiceNow 사내 시스템 데이터의 색인 및 검색을 연계합니다.

🔌 M365 엔터프라이즈 커넥터

임직원의 이메일 내역 및 원드라이브 첨부 문서를 색인하여 업무 콘솔 내에서 통합 RAG 검색 환경을 지원합니다.

🛡️ 접근 제어 목록(ACL) 동기화

원본 데이터 소스의 개별 사용자 접근 권한(ACL) 정보가 색인에 실시간 동기화되므로, 원본 시스템에서 열람 권한이 없는 데이터는 검색 결과에 절대 나타나지 않습니다.

Step 3.3 커넥터 거버넌스

심화: Actions (쓰기 권한) Human-in-the-Loop

에이전트가 외부 시스템에 쓰기 작업을 수행할 때 보안을 안전하게 통제합니다.

⚠️ 승인 단계 필수화 (Human-in-the-Loop)

외부 시스템에 변경을 가하는 Action 트리거 발생 시, 자동 처리를 일시 중지하고 사용자 화면에 [실행 승인 요청] 창을 띄웁니다.

  • 권한 토큰 분리: 조회(Read-only) 권한과 변경(Write Action) 권한을 IAM 정책에서 엄격히 분리 적용합니다.
  • 감사 내역 기록: Action 실행자, 승인 일시, 파라미터 정보가 Cloud Audit Logs에 보관됩니다.
Step 3.4 에이전트 관리

전사 에이전트 레지스트리 (Agent Registry) 관제

사내 각 조직에서 배포한 커스텀 에이전트의 현황을 중앙 관리 콘솔에서 모니터링하고 권한을 통제합니다.

👁️ 활성 상태 모니터링

등록된 에이전트의 배포 수, 부서별 활성 사용량, 매핑된 데이터 소스 연결 현황을 중앙에서 조회합니다.

🔐 ACL 접근 범위 통제

인사, 재무 등 민감 데이터를 다루는 에이전트는 인가된 특정 보안 그룹만 접근할 수 있도록 접근 제어 목록을 설정합니다.

🛑 에이전트 킬 스위치 (Kill Switch)

보안 정책 위반이나 비정상 호출이 감지된 에이전트를 콘솔에서 즉시 '비활성화(Disable)'하여 호출을 전면 차단합니다.

Step 3.4 에이전트 관리

실습: 에이전트 ACL 감사 및 비활성화

관리자 콘솔에서 정책 위반 에이전트를 확인하고 활성 상태를 제어하는 실습 절차입니다.

📋 통제 실습 단계

  • 1단계 (조회): Agent Registry 목록에서 대상 에이전트(`[비공식_재무_급여_계산_봇]`) 선택
  • 2단계 (권한 검토): 접근 권한 그룹이 `All Employees(전사)`로 과다 설정되어 있는지 감사
  • 3단계 (비활성화): 상단의 [Disable Agent] 버튼을 클릭하여 서비스 접근을 차단하고 소유자에게 알림 발송
Step 3.5 Model Armor

Model Armor: 인라인 보안 방화벽 3대 지표

실시간 데이터 입출력 방화벽인 Model Armor를 통해 제어하는 주요 데이터 검열 지표입니다.

🛡️ 1. 민감 정보(PII) 탐지

주민등록번호, 전화번호, 금융 정보 등 개인식별정보(PII) 패턴 감지 시 마스킹 또는 요청 차단 규칙을 적용합니다.

🚫 2. 프롬프트 인젝션 방어

시스템 지시어 우회(Jailbreak) 및 시스템 프롬프트 유출 시도를 탐지하여 모델 인퍼런스 전송 전 필터링합니다.

☣️ 3. 유해 콘텐츠 검열

욕설, 혐오 표현, 비윤리적 지시문 등 기업 업무에 부적합한 입력 및 출력 데이터를 사전에 검출합니다.

Step 3.5 Model Armor

Model Armor 7대 보안 테스트 케이스 매트릭스

엔터프라이즈 환경에서 필수적으로 검증해야 하는 7가지 보안 시나리오 및 방어 메커니즘입니다.

🌐 1. 악성 웹 차단

피싱 및 악성 URL 파싱 차단

🔒 2. PII 마스킹

주민번호·카드번호 인라인 마스킹

🚫 3. 인젝션 방어

시스템 프롬프트 탈취 원천 차단

☣️ 4. 유해 콘텐츠 검열

비윤리적·공격적 표현 자동 필터

Step 3.5 Model Armor 실습

부서별 차등 임계값 정책 설정 (CS vs R&D)

조직 단위(OU) 및 부서 특성에 맞춰 Model Armor 필터링 강도를 조정하는 설정 방안입니다.

🎧 고객 상담 부서 (CS)

엄격 모드 (High): 대화 내 고객 개인식별정보(PII) 유출을 100% 방지하기 위해 개인정보 마스킹 강도를 최대로 유지합니다.

💻 연구 개발 부서 (R&D)

유연 모드 (Moderate): 소스 코드, SQL 쿼리, 기술 스크립트 등 특수 구문의 오탐을 방지하여 엔지니어의 개발 생산성을 보장합니다.

Step 3.6 감사 관제

감사 로그 SIEM 연계: BigQuery 실시간 관제

에이전트 호출, 색인에서 문서를 참조한 내역은 Cloud Audit Logs를 거쳐 BigQuery 데이터셋으로 전송됩니다.

🔍 호출 내역 완벽한 추적성

호출 일시, 요청 사용자 이메일, 사용된 에이전트 ID, 참조된 문서 URI 등 상세 감사 정보를 영구 보관 및 실시간 조회합니다.

🚨 SIEM 툴 연동 분석

Splunk, Chronicle 등 사내 SIEM 시스템과 쿼리를 연동하여 단기간 내 다량 문서 참조 발생 시 보안 이벤트 알림을 발송합니다.

Step 3.6 감사 관제 실습

BigQuery 실시간 감사 로그 조회 SQL

관리자가 BigQuery 콘솔에서 단시간 내 다수 문서를 참조한 이상 징후 호출 내역을 조회하는 쿼리 실습입니다.

📋 SIEM 탐지 SQL 예제

SELECT prolog.timestamp, prolog.caller_ip, prolog.user_email, prolog.agent_id, prolog.action_type, prolog.query_text, prolog.cited_docs FROM `sys-audit-prod-01.gemini_siem.cloudaudit_googleapis_com_data_access` AS prolog WHERE prolog.timestamp >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 1 HOUR) AND prolog.action_type = 'RAG_CITATION_QUERY' AND ARRAY_LENGTH(prolog.cited_docs) >= 15 ORDER BY prolog.timestamp DESC;

💡 결과: 설정된 시간 범위 내 기준치(15개) 이상의 문서를 인용한 사용자 IP 및 요청 이력 리스트가 출력됩니다.

Step 3.7 확장 & ROI

Chrome 옴니바 연동 & ROI 재무 시뮬레이션

Chrome 주소창 연동을 통한 전사 도입 확산 및 경영진 보고용 ROI 산출 공식입니다.

🌐 Chrome 주소창 옴니바 4단계 호출

주소창에 @gemini [질의] 입력만으로 사내 Gemini Enterprise 콘솔을 즉시 호출하여 전사 사용자 접근성을 극대화합니다.

📈 ROI 정량적 산출 공식

ROI(%) = [(인당 절감시간 × 시간당 임금 × 사용자 수) - 총 라이선스 비용] / 총 비용 × 100

월 10시간 절감 가정 시, 도입 6개월 이내 손익분기점(BEP) 달성이 가능합니다.
