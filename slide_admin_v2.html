멀티 리전 이중화 & 고가용성(HA) 아키텍처

🌐 리전별 역할 분담
  • Primary: asia-northeast3 (서울)
    주요 운영 트래픽 처리 및 색인 데이터 로컬 보관 (데이터 주권 준수)

    재해 복구(DR) 대비 글로벌 백업 및 페일오버 리전 활용

🛡️ 네트워크 및 암호화 통제

WIF 키리스 인증 & Cloud Identity 자동 동기화

장기 보안 자격증명 파일의 유출 위험을 제거하기 위해 WIF 기반 OIDC 인증을 구성합니다.

🔑 WIF 기반 키리스(Keyless) 연동

사내 IDP(Okta, Microsoft Entra ID 등)와 구글 클라우드를 OIDC 표준 프로토콜로 직접 연결하여, 정적 JSON 키 파일 없이 1시간 유효 단기 토큰으로 안전하게 인증합니다.

✨ 정적 서비스 계정 키 파일 100% 제거
👥 인사 조직 정보(HRIS) 자동 동기화

Cloud Identity 연동 파이프라인을 통해 임직원의 퇴사, 부서 이동, 직급 변경 발생 시 Gemini Enterprise IAM 접근 권한 및 그룹 ACL이 실시간으로 자동 갱신 및 회수됩니다.

🚫 권한 미회수(Orphan Account) 사고 원천 방지

타사 업무 도구의 데이터를 색인할 때 원본 접근 권한(ACL)을 100% 상속합니다.

🔌 엔터프라이즈 멀티 커넥터
  • Microsoft 365: Outlook 이메일, OneDrive, SharePoint 첨부 색인
  • ServiceNow: 사내 ITSM 티켓, 장애 이력 및 지식 베이스 검색
  • Salesforce / Jira: 영업 파이프라인 및 이슈 트래커 통합
💼 전사 분산 업무 데이터의 단일 검색창 통합
🛡️ 접근 제어 목록(ACL) 실시간 상속

원본 시스템의 개별 파일 권한 정보가 색인에 동기화되므로, 원본 시스템에서 열람 권한이 없는 사용자는 Gemini 검색 결과에서 해당 문서를 절대 조회할 수 없습니다.

🔒 사내 민감 급여/인사 문서 비인가 열람 0% 보장

Actions 쓰기 통제 & Human-in-the-Loop (HITL)

에이전트가 외부 시스템을 변경하는 작업을 수행할 때 승인 절차를 필수화합니다.

1️⃣ 조회/쓰기 권한 분리

단순 조회(Read-only)와 시스템 변경(Write/Delete) 권한을 IAM 토큰 레벨에서 엄격히 분리

🔑 IAM Token Separation
2️⃣ 실행 승인 팝업 (HITL)

외부 API 호출 발생 시 사용자 화면에 승인 모달을 띄워 파라미터 확인 후 실행

👤 Explicit User Consent
3️⃣ 감사 추적성 전수 기록

승인자 이메일, 승인 일시, 전달된 파라미터 원문이 Cloud Audit Logs에 영구 기록

📝 Immutable Audit Trail
⚠️ Action 통제 효과
에이전트 오작동으로 인한 외부 데이터 훼손 사고 100% 방지

실습 1. 정책 위반 에이전트 킬 스위치 작동

관리자 콘솔에서 비인가 에이전트를 감사하고 활성 상태를 즉시 제어합니다.

📋 3단계 킬 스위치 실행 절차
  • 1단계 (조회): Agent Registry 목록에서 대상 에이전트 선택
  • 2단계 (감사): 접근 그룹이 '전사(All Employees)'로 과다 설정된 상태 확인
  • 3단계 (차단): 상단의 [Disable Agent] 버튼 클릭
  • 4단계 (검증): 사용자 대화창에서 @호출 시 '비활성화된 에이전트' 에러 반환 확인
⚡ 즉시 반영 (0.5초 이내 전사 호출 차단 완료)
💡 관리자 알림 & 복구 가이드

비활성화 즉시 에이전트 등록자에게 사내 이메일로 정책 위반 소명 요청이 자동 발송되며, 보안 검토 통과 후 언제든 재활성화(Enable)가 가능합니다.

✨ 자동화된 사고 대응 및 복구 워크플로우

비상 상황 시 즉각적인 서비스 격리 및 보안 위험 최소화

실습 2. 부서별 차등 임계값 설정 (CS vs R&D)

조직 단위(OU) 특성에 맞춰 Model Armor 필터링 강도를 최적화합니다.

🎧 고객 상담 부서 (CS) — 엄격 모드 (High)
  • PII 민감도: High (전화번호, 계좌번호, 주소 100% 마스킹)
  • 유해성 필터: High (고객 응대 품격 유지를 위한 강한 필터)
  • 주요 목적: 대고객 개인정보 유출 리스크 0% 달성
🛡️ 고객 접점 컴플라이언스 완벽 준수
💻 연구 개발 부서 (R&D) — 유연 모드 (Moderate)
  • PII 민감도: Moderate (테스트용 더미 데이터 오탐 방지)
  • 코드/SQL 허용: 특수 구문 및 명령어 오탐 차단 완화
  • 주요 목적: 개발자의 코딩 및 디버깅 생산성 보장
⚡ 보안과 개발 생산성의 완벽한 균형
⚖️ 맞춤 정책
일률적인 차단 대신 부서 업무 목적에 최적화된 맞춤 필터링

실습 3. BigQuery 실시간 이상 징후 감사 SQL

단시간 내 다수 문서를 인용한 이상 징후 호출 내역을 조회하는 실무 쿼리입니다.

📋 SIEM 탐지 SQL 쿼리
BigQuery SQL
SELECT prolog.timestamp, prolog.caller_ip, prolog.user_email, prolog.agent_id, prolog.action_type, prolog.query_text, prolog.cited_docs FROM `sys-audit-prod-01.gemini_siem.cloudaudit_googleapis_com_data_access` AS prolog WHERE prolog.timestamp >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 1 HOUR) AND prolog.action_type = 'RAG_CITATION_QUERY' AND ARRAY_LENGTH(prolog.cited_docs) >= 15 ORDER BY prolog.timestamp DESC;
✅ 쿼리 실행 결과 해석
  • 이상 징후 탐지: 단기간 내 비정상적인 대량 문서 스캔 감지
  • 계정 격리 조치: 이상 패턴 확인 시 관리자가 즉시 세션 만료 및 감사 착수
  • 정기 리포팅: 월간 보안 거버넌스 감사 보고서에 통계 데이터 자동 첨부
✨ 데이터 반출(Exfiltration) 시도 사전 차단
🔍 SIEM 모니터링
실시간 감사 쿼리로 잠재적 보안 위협을 선제적으로 감지
